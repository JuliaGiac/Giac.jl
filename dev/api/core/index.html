Core API

The main Giac module provides core types and functions for symbolic computation.

Giac — Module
Giac

A Julia wrapper for the GIAC computer algebra system.

Provides symbolic expression evaluation, calculus operations, polynomial manipulation, and linear algebra with a Julia-native API.

Core Exports

  • GiacExpr: Symbolic expression type
  • GiacContext: Evaluation context
  • GiacMatrix: Symbolic matrix type
  • GiacError: Exception type for GIAC errors
  • giac_eval: Evaluate expression strings
  • @giac_var: Create symbolic variables from Julia symbols
  • to_julia: Convert GiacExpr to Julia types
  • invoke_cmd: Universal command invocation (works for ALL commands)

Command Access

GIAC commands are available through the Giac.Commands submodule:

using Giac

# Use invoke_cmd for any command (always available)
invoke_cmd(:factor, giac_eval("x^2-1"))
invoke_cmd(:sin, giac_eval("pi/6"))  # Works for conflicting commands too

# Import commands selectively (recommended)
using Giac.Commands: factor, expand, diff
factor(giac_eval("x^2-1"))

# Or import all ~2000+ commands
using Giac.Commands
factor(giac_eval("x^2-1"))
ifactor(giac_eval("120"))

Quick Start

using Giac

# Declare symbolic variables with @giac_var macro
@giac_var x y

# Build and manipulate expressions using Giac.Commands
using Giac.Commands: factor, expand, diff
expr = giac_eval("x^2 + 2*x*y + y^2")
result = factor(expr)   # (x+y)^2

# Or use string-based evaluation directly
result = giac_eval("factor(x^2 - 1)")
println(result)  # (x-1)*(x+1)

See also

  • Giac.Commands: Submodule with all exportable commands
  • invoke_cmd: Universal command invocation

Giac.GiacInput — Type
GiacInput

Union type representing all valid input types for GIAC command functions.

This type alias enables generated GIAC command functions to accept native Julia types in addition to GiacExpr, providing a more ergonomic API.

Supported Types

  • GiacExpr: Native GIAC expressions
  • Number: All Julia numeric types (Integer, AbstractFloat, Rational, Complex, etc.)
  • String: String representations of GIAC expressions
  • Symbol: Variable names (e.g., :x, :y)
  • AbstractVector: Julia vectors/arrays (converted to GIAC list syntax)

@giac x y

det([[1,2],[3,4]])            # Nested vectors for matrices

Numbers and approximate equality

GiacExpr(x) builds an expression from any Julia number, like convert(GiacExpr, x): GiacExpr(3//4) is the exact 3/4, and GiacExpr.(M) converts a numeric matrix entry by entry.

Base.isapprox — Method
isapprox(a::GiacExpr, b::GiacExpr; atol = 0, rtol, nans = false)
a ≈ b

Approximate equality, with Julia's tolerances.

  • Expressions without free symbols are compared by their numeric values: sqrt(GiacExpr(2)) ≈ 1.4142135623730951.
  • Expressions in symbols are approximately equal when they are equal (==), or when the numeric coefficients of their monomials are approximately equal, the coefficients being compared as one vector: 1.0000000001x + y ≈ x + y. Non-rational parts such as sin(x) count as variables of the monomials.
  • An expression with no numeric value, or a coefficient without one, is approximately equal only to what it equals.

A GiacExpr can also be compared with a Julia number, in either order.

source
@giac_var x y
sqrt(GiacExpr(2)) ≈ 1.4142135623730951   # true: compared by numeric value
1.0000000001x + y ≈ x + y                # true: coefficients compared
sin(x)^2 + cos(x)^2 ≈ 1                  # true: the expressions are equal
isapprox(GiacExpr(π), 355//113; rtol = 1e-6)  # true

Symbolic Variables

Giac.@giac_var — Macro
@giac_var x y::(integer, positive) z[1:4] u[1:2]::integer v=>"𝑣" w(t)

Declare Giac variables and bind them to Julia variables of the same name. Returns a tuple of what was declared.

Each argument is one of:

  • x: a symbolic variable.
  • x::assumption or x::(assumption, ...): a variable with assumptions (see below). Symbolics.jl-style metadata, x [positive, real] or x [domain = Real], is also accepted.
  • z[1:4], z[1:2, -1:1]: an array of variables z₁, z₂, … with the shape of the ranges. Ranges may use variables, e.g. z[1:n], and can be combined with assumptions: u[1:2]::positive.
  • w(t), f(x, y): a symbolic function of the given variables. Functions take no assumptions.
  • v => "𝑣": bind the Julia variable v to the Giac name 𝑣. Works with functions (w(t) => "W"); add assumptions with parentheses: (v => "𝑣")::positive.

Commas between arguments are allowed: @giac_var x, y, z.

Assumptions

  • A domain: real, complex, rational, integer (or Real, Complex, Rational, Integer).
  • A named range: positive, negative, nonnegative, nonpositive, finite.
  • A comparison with a bound: <(b), <=(b), >=(b), >(b). The bound is evaluated where the macro is called, so >(c) uses the value of c.
  • A function: [domain = v -> v > 0], called with the new variable; it must return a Giac condition.

An unknown assumption is an error when the macro is expanded.

Declaring a variable resets it: any value bound with := and any earlier assumption (including one made with assume) is removed first. Assumptions are recorded in Giac's global state, so they apply for the rest of the session, like assume.

Example

julia> @giac_var x y::(integer, positive) z[1:2,-1:1] u[1:2]::positive v=>"𝑣" w(t)
(x, y, GiacExpr[z₁_₋₁ z₁_₀ z₁_₁; z₂_₋₁ z₂_₀ z₂_₁], GiacExpr[u₁, u₂], 𝑣, w(t))

julia> Giac.Commands.about(x)
GiacExpr: x

julia> Giac.Commands.about(y)
GiacExpr: assume[integer,[line[0,+infinity]],[0]]

julia> z
2×3 Matrix{GiacExpr}:
 GiacExpr: z₁_₋₁  GiacExpr: z₁_₀  GiacExpr: z₁_₁
 GiacExpr: z₂_₋₁  GiacExpr: z₂_₀  GiacExpr: z₂_₁

julia> Giac.Commands.about(u[2])
GiacExpr: assume[[],[line[0,+infinity]],[0]]

julia> v
GiacExpr: 𝑣

julia> w
GiacExpr: w(t)

julia> n = 3; @giac_var a[1:n]; a
3-element Vector{GiacExpr}:
 GiacExpr: a₁
 GiacExpr: a₂
 GiacExpr: a₃

julia> @giac_var x::(integer, >(2)); Giac.Commands.about(x)
GiacExpr: assume[integer,[line[2,+infinity]],[2]]

julia> @giac_var x::(>(pi)); Giac.Commands.about(x)
GiacExpr: assume[[],[line[pi,+infinity]],[pi]]

Giac.@giac_several_vars — Macro
@giac_several_vars base dims...

Create multiple indexed symbolic variables for N-dimensional tensors.

This macro generates multiple GiacExpr variables in the calling scope with names formed from a base name and indices. It supports any number of dimensions and returns a tuple of all created variables.

Arguments

  • base: Symbol - The base name for variables (e.g., a, coeff, α)
  • dims...: Integer literals or range expressions - Dimensions of the tensor (1 or more)
    • Integer n: Creates indices 1:n (backward compatible)
    • UnitRange a:b: Creates indices from a to b
    • StepRange a:s:b: Creates indices from a to b with step s

Returns

  • Tuple{GiacExpr...}: A tuple containing all created variables in lexicographic order

Naming Convention

  • If all indices are in 0-9: indices are concatenated directly (e.g., a123)
  • If any index > 9: underscore separators are used (e.g., a_1_10)
  • Negative indices: m prefix for minus (e.g., -1 → m1, so c_m1)

Examples

1D vector:

@giac_several_vars a 3
# Creates: a1, a2, a3 and returns (a1, a2, a3)
a1 + a2 + a3  # Symbolic sum

# Capture return value
vars = @giac_several_vars c 4
length(vars)  # 4

2D matrix:

result = @giac_several_vars m 2 3
# Creates: m11, m12, m13, m21, m22, m23
# Returns: (m11, m12, m13, m21, m22, m23)
length(result)  # 6

3D tensor:

@giac_several_vars t 2 2 2
# Creates: t111, t112, t121, t122, t211, t212, t221, t222
# Returns tuple of 8 variables

Large dimensions (separator used):

@giac_several_vars b 2 10 3
# Creates: b_1_1_1, b_1_1_2, ..., b_2_10_3

Unicode base names:

@giac_several_vars α 2
# Creates: α1, α2

0-based indexing with UnitRange:

@giac_several_vars psi 0:2
# Creates: psi0, psi1, psi2 and returns (psi0, psi1, psi2)

2D with custom ranges:

@giac_several_vars T 0:1 0:2
# Creates: T00, T01, T02, T10, T11, T12

Negative indices:

@giac_several_vars c -1:1
# Creates: c_m1, c_0, c_1 (m = minus, to avoid GIAC parsing issues)

StepRange:

@giac_several_vars q 0:2:4
# Creates: q0, q2, q4

Mixed arguments (integer and range):

@giac_several_vars mixed 2 0:1
# First dim: 1:2, second dim: 0:1
# Creates: mixed10, mixed11, mixed20, mixed21

Edge cases:

@giac_several_vars x 0     # Returns empty tuple ()
@giac_several_vars y 1     # Creates y1, returns (y1,)
@giac_several_vars z 2 0   # Returns empty tuple (0 in any dim)
@giac_several_vars e 5:4   # Returns empty tuple (empty range)

See also

  • @giac_var: For creating single symbolic variables
  • giac_eval: For evaluating string expressions

Giac.@giac_matrix — Macro
@giac_matrix A[m, n] P[n, n] [posdef] W[3, 3] [skew] V[2, 2]::(upper, real)

Declare matrices of symbolic entries and bind them to Julia variables. Each matrix is a Matrix{GiacExpr} whose entries are named like the arrays of @giac_var: A₁_₁, A₁_₂, …. The sizes may be integers (A[2, 3], indices from 1) or ranges (C[0:1, 0:1]), and may use variables (B[n, n]). Returns a tuple of the matrices.

A structure, a property and assumptions on the entries are written in brackets after the matrix (P[2, 2] [symmetric]) or after :: (P[2, 2]::symmetric), several of them together:

  • a structure, for a square matrix:
    • symmetric: entry (j, i) is entry (i, j), named with i ≤ j;
    • skew: entry (j, i) is minus entry (i, j), the diagonal is 0;
    • diagonal: the entries off the diagonal are 0;
    • upper, lower: triangular, the rest 0.
  • a property: posdef or negdef, a positive or negative definite matrix. It makes the matrix symmetric (unless it is declared diagonal) and its diagonal entries positive (negative), the consequence Giac can record, since its assumptions are on variables. The property itself is kept for Giac.matrix_properties.
  • assumptions on the free entries, as in @giac_var: real, positive, >(0), ….

Declaring a matrix resets its entries, as @giac_var does.

@giac_matrix A[2, 2] P[2, 2] [posdef]
P★ = solve(P*A + A'*P ~ -I, P)       # with the linear algebra on arrays of expressions

Assumptions for one block and settings

Giac.assuming — Function
assuming(f, conditions...)

Run f() with GIAC assumptions in force, then undo them. A condition is a relation (k > 0, x < y) or a domain x => :integer (:real, :integer, :complex, :rational). Several conditions on one variable combine, and they add to what the variable was declared with (@giac_var k::real).

When the block ends, after an error too, every variable named in the conditions gets back the state GIAC held for it before (its declared assumptions, or none), and so does every setting of giac_settings. The GIAC lock is held for the whole block: other tasks wait, and none sees the temporary assumptions.

@giac_var k
assuming(k > 0) do
    Giac.Commands.simplify(sqrt(k^2))       # k
end
Giac.Commands.simplify(sqrt(k^2))           # abs(k)

Giac.assumptions — Function
assumptions(x::GiacExpr) -> Giac.Assumptions

What GIAC assumes of the variable x, read from about(x): its domain, the union of intervals it lies in (with open or closed ends), the excluded points, or its value if it is assigned. The record holds only what reached GIAC: a condition GIAC does not keep, such as x != 3, does not appear, which lets a caller check its premises against it.

@giac_var a
Giac.Commands.assume((a > 0) & (a <= 10))
assumptions(a)              # Assumptions(]0, 10])
assumptions(a).intervals    # [(lo = 0, hi = 10, lo_closed = false, hi_closed = true)]

Giac.Assumptions — Type
Giac.Assumptions

What GIAC assumes of a variable, as returned by assumptions:

Function Syntax for @giac_var

The @giac_var macro supports function notation for defining symbolic functions that depend on other variables. This is useful for differential equations and calculus with unknown functions.

Single-variable functions:

@giac_var u(t)        # u is a GiacExpr representing "u(t)"
@giac_var t           # t is the independent variable
diff(u, t)            # Symbolic derivative of u with respect to t

Multi-variable functions:

@giac_var f(x, y)     # f represents "f(x,y)"
@giac_var x y
diff(f, x)            # Partial derivative ∂f/∂x
diff(f, y)            # Partial derivative ∂f/∂y

Mixed declarations:

@giac_var t x y u(t) f(x, y)
# Creates: t, x, y as simple variables
#          u as "u(t)", f as "f(x,y)"

Common use case - ODEs:

@giac_var t u(t)
# Express ODE: u''(t) + u(t) = 0

Common use case - PDEs:

@giac_var x y u(x, y)
# Laplacian: ∂²u/∂x² + ∂²u/∂y²
laplacian = diff(diff(u, x), x) + diff(diff(u, y), y)

Callable GiacExpr (Function Evaluation)

GiacExpr objects are callable, allowing natural function evaluation syntax like u(0). This is essential for specifying ODE initial conditions.

Basic function evaluation:

@giac_var u(t)
u(0)           # Returns GiacExpr: "u(0)"
u(1)           # Returns GiacExpr: "u(1)"

ODE initial conditions:

using Giac.Commands: diff, desolve
@giac_var t u(t) tau U0

# ODE: τu' + u = U₀ with u(0) = 1
ode = tau * diff(u, t) + u ~ U0
initial = u(0) ~ 1
desolve([ode, initial], u)

Derivative initial conditions (using D operator):

using Giac.Commands: desolve
@giac_var t u(t)

# First derivative at t=0: u'(0) = 1
Differential(t)(u)(0) ~ 1

# Second derivative at t=0: u''(0) = 0
Differential(t, 2)(u)(0) ~ 0

# Full example: solve u'' + u = 0 with u(0)=1, u'(0)=0
ode = Differential(t, 2)(u) + u ~ 0
u0 = u(0) ~ 1
du0 = Differential(t)(u)(0) ~ 0
desolve([ode, u0, du0], t, :u)  # Returns: cos(t)

D Operator (Derivative Operator)

The D operator follows SciML/ModelingToolkit conventions for expressing derivatives:

@giac_var t u(t)

# Create derivative expressions
Differential(t)(u)        # First derivative u'
Differential(t, 2)(u)     # Second derivative u'' (chained)
Differential(t, 2)(u)     # Second derivative u'' (direct)
Differential(t, 3)(u)     # Third derivative u'''

# Use in ODE equations
ode = Differential(t, 2)(u) + u ~ 0    # u'' + u = 0

# Use in initial conditions (produces prime notation for GIAC)
Differential(t)(u)(0) ~ 1              # u'(0) = 1
Differential(t, 2)(u)(0) ~ 0           # u''(0) = 0

Complete ODE examples:

using Giac
using Giac.Commands: desolve

# 2nd order: u'' + u = 0, u(0)=1, u'(0)=0
@giac_var t u(t)
result = desolve([Differential(t, 2)(u) + u ~ 0, u(0) ~ 1, Differential(t)(u)(0) ~ 0], t, :u)
# Returns: cos(t)

# 3rd order: y''' - y = 0, y(0)=1, y'(0)=1, y''(0)=1
@giac_var t y(t)
result = desolve([Differential(t, 3)(y) - y ~ 0, y(0) ~ 1, Differential(t)(y)(0) ~ 1, Differential(t, 2)(y)(0) ~ 1], t, :y)
# Returns: exp(t)
desolve function argument

When calling desolve, pass the function name as a Symbol (:u, :y) rather than the function expression (u, y), since GIAC expects just the name, not u(t).

Multi-variable function evaluation:

@giac_var f(x, y) a b
f(0, 0)        # Returns "f(0,0)"
f(a, b)        # Returns "f(a,b)"
f(1, 2)        # Returns "f(1,2)"

Exact Numbers

A decimal literal is a binary floating-point number before Giac sees it: 0.1 is the double nearest $1/10$, and 0.1 + 0.2 is 0.30000000000000004 in Julia. Giac keeps such a number as a float, and its doubles carry fewer mantissa bits than Julia's Float64 (some bits hold the type tag), so what Giac computes from them is good to about 12 significant digits: sqrt(convert(GiacExpr, 2.0)) differs from Julia's sqrt(2.0) by about 3e-12. The same goes for 2π (a Float64 product, computed before any Giac code runs) and for sqrt(2) or 1/2 of integer literals.

@exact rewrites the numbers of the code it is given into exact Giac numbers before Julia computes with them. It is the recommended way to write decimals in symbolic code:

using Giac
using Giac.Commands: factor, solve
@giac_var x

0.1 + 0.2                        # 0.30000000000000004 (a Julia Float64)
@exact 0.1 + 0.2                 # 3/10

2π * x                           # 6.283185307179586*x
@exact 2π * x                    # 2*pi*x

solve(x^2 - 0.5, x)              # list[-0.707106781187,0.707106781187]
@exact solve(x^2 - 0.5, x)       # list[-1/2*sqrt(2),1/2*sqrt(2)]

factor(x^2 + 0.1x)               # x*(x+0.1)
@exact factor(x^2 + 0.1x)        # x*(10*x+1)/10

@exact exp(0.5) + sqrt(2) / 2    # exp(1/2)+sqrt(2)/2
Giac.@exact — Macro
@exact expr

expr with its numbers kept exact. A float literal is read as the decimal it is written as, so @exact 0.1 + 0.2 is the Giac fraction 3/10 (Julia's 0.1 + 0.2 is 0.30000000000000004); @exact 2π * x is 2πx with Giac's π rather than 6.283…*x, and @exact sqrt(2) / 2 is √2/2. A function cannot do this, as 0.1 and 2π are floats before any function sees them.

Rewritten into exact GiacExpr values: float literals (each read from its shortest decimal form, 2.5e-3 is 1/400; big(0.1) and big"0.1" too), π, pi and ℯ, sqrt and cbrt of an integer literal, an integer literal to a fractional or negative power (2^(1/3), 2^-1), and the quotient 1/2 of two integer literals. Left as written: integer literals and integer arithmetic (2 * 3 is the Julia 6), names, whatever their value (y = 0.1; @exact y * x still has the float), qualified constants (Base.pi), quoted code, and code inside another macro call (@exact nested in it expands on its own). A block works too. A name assigned an integer or a rational by the macro's own assignments (those of its block, not of a loop or function inside it) is bound to the Giac number, so that what is computed from it later is exact as well.

All literals of expr are rewritten, so keep numeric code (ranges, tolerances, plotting) out of it.

@exact 0.1 + 0.2                             # 3/10
@giac_var x a::positive
@exact 0.5x^2 - 1.25                         # 1/2*x^2-5/4
φ = @exact sqrt(2 / a) * sin(2π * x / a)     # √(2/a) sin(2πx/a)
@exact three = 3                             # a Giac 3: sqrt(three) is √3

What is left as written:

  • Integers and integer arithmetic: @exact 2 * 3 is the Julia 6, and an integer literal too large for Int stays an Int128 or a BigInt, which Giac receives exactly. Julia's integer overflow still applies, so write big(10)^20 rather than 10^20.
  • Floats that are not literals: with y = 0.1, @exact y * x keeps the float held by y; only the digits written inside the macro call are read. For a float computed elsewhere, Giac's exact command (Giac.Commands.exact(convert(GiacExpr, y))) gives a nearby fraction.
  • Qualified constants (Base.pi), quoted code (:(0.1)), and the code of other macros inside the expression: put @exact inside the other macro call rather than around it. A nested @exact expands on its own.

A name assigned by the macro's own assignments (in its block, not in a loop or function inside it) is bound to the Giac number, so what is computed from it later is exact as well:

    h = 0.1                      # 1/10, a GiacExpr
    three = 3                    # a Giac 3: sqrt(three) is sqrt(3)
end

Every literal of the expression is rewritten, so keep numeric code such as ranges, tolerances or plotting outside @exact.

Vector Input Support

GIAC commands accept Julia vectors directly, enabling natural syntax for systems of equations and matrix operations:

using Giac
using Giac.Commands: solve, det_minor, inverse
@giac_var x y z

# Solve systems of equations with vector syntax
solve([x + y ~ 1, x - y ~ 0], [x, y])  # Returns [[1/2, 1/2]]

# Three-variable system
solve([x + y + z ~ 6, x - y ~ 0, y + z ~ 4], [x, y, z])

# Matrix operations with nested vectors

inverse([[1, 2], [3, 4]])    # Returns inverse matrix

See GiacInput for the full list of supported input types.

Symbolic matrices

Matrices as single symbols, with products that do not commute (see Linear Algebra).

Giac.@matsym — Macro
@matsym A[n, n] P[n, n]::posdef Q[n, n]::orthogonal x[n] B[n, m]

Declare symbolic matrices: each name is bound to a MatExpr standing for a matrix of the given size, whose products do not commute. A size is a number, a name (n; use $k for the value of a Julia variable k), or a product of them (m*n, the size of a Kronecker product); x[n] is an n × 1 column. Tags after :: (or a tuple of them) are properties: symmetric, skew, diagonal (symmetric), orthogonal, posdef and negdef (symmetric and invertible), invertible.

The algebra of matrices holds as expressions are built: (A*B)' == B'*A', inv(A*B) == inv(B)*inv(A), P' == P, Q'*Q == I, x'*A'*P*x + x'*P*A*x == 2*x'*P*A*x (a 1×1 term is its transpose). tr and det give scalars (tr(A*B) == tr(B*A)), det Q = ±1 for an orthogonal Q, det W = 0 for a skew W of odd size. substitute(M, A => entries, …) gives the explicit matrix; differential, ∇, jacobian, hessian and derivative do matrix calculus, and quadratic_form takes a quadratic form apart; [A B; C D] is a block matrix with products, inv and det.

Giac.evaluate_with_diagnostics — Function
evaluate_with_diagnostics(f; context=DEFAULT_CONTEXT[]) -> GiacEvalResult

Call f() and return its result together with the messages GIAC logged while it ran. Without the capture, these messages go to stderr.

The value is exactly what f() returns; nothing is read back from the log into it. A definite integral with no closed form stays unevaluated, and the numeric estimate GIAC prints is available only as a diagnostic.

using Giac
using Giac.Commands: integrate
@giac_var x
out = evaluate_with_diagnostics() do
    integrate(log(1 + x) / (1 + x^2), x, 0, 1)
end
out.value                  # integrate(ln(1+x)/(1+x^2),x,0,1)
out.diagnostics[1].level   # DiagnosticLevel.INFO
out.diagnostics[1].text    # "∫ ~= 0.272198261288"

Keyword arguments

  • context::GiacContext: also capture the log of this context, for code that evaluates through giac_eval(expr, ctx). The default context is always captured. When both produce text, the default context's log comes first.

Notes

  • Captures nest: an inner call sees its own messages, and the outer call sees them too.
  • The GIAC lock is held while f runs, so messages from other tasks do not end up in the capture. Do not wait inside f for another task that itself calls GIAC: it would block on the lock.
  • The default context is per OS thread. If f yields and its task resumes on another thread, the capture cannot be closed where it was opened; a warning is issued and the default context's log is lost.
  • If f throws, the log stream is restored and the exception propagates; the log is dropped. To keep it, catch inside f: evaluate_with_diagnostics(() -> try g() catch e; e end).
  • Messages GIAC writes straight to stderr/stdout, bypassing its log stream, are not captured.
  • With libgiac_julia_jll 0.6 or later, the wrapper captures GIAC's log stream on the C++ context. With an older wrapper, stderr is redirected instead, where GIAC's log stream writes by default: then anything written to stderr while f runs is captured too (a Julia warning, for instance), and the context keyword has no effect of its own.

Giac.GiacDiagnostic — Type
GiacDiagnostic(level, text, raw)

One line GIAC wrote to its log stream during an evaluation.

Fields

  • level::DiagnosticLevel.T: severity, inferred from the text (see below)

  • text::String: the message, without GIAC's // comment prefix

  • raw::String: the line exactly as GIAC wrote it

  • kind::Symbol: what the message says, for the messages GIAC is known to write:

    • :estimate: a numeric estimate of a result GIAC leaves unevaluated (∫ ~= 0.27…);

How numbers are read

to_julia, float, Float64(g), convert(Float64, g), Complex(g) and Rational(g) read a GIAC number as follows.

Doubles (DOUBLE) are read from the decimal GIAC prints for them, at Digits significant digits (12 by default). This applies to the parts of a complex double and to the elements of a vector or matrix too:

to_julia(giac_eval("0.1+0.2"))               # 0.3
to_julia(giac_eval("sqrt(2.0)"))             # 1.41421356237
to_julia(giac_eval("sqrt(2.0) + sqrt(3.0)*i"))  # 1.41421356237 + 1.73205080757im

GIAC's doubles carry fewer mantissa bits than Julia's Float64: GIAC keeps its type tag in the low byte of the 64-bit word, which leaves 45 bits of mantissa instead of 53. The bits GIAC stores are therefore not a better reading than the printed decimal (for 0.1+0.2 they would read as 0.29999999999999). When you need more than 12 digits, ask GIAC for a multiprecision value with Giac.Commands.evalf(x, n), or keep the input exact: 1/10, exact(0.1) and Julia's 1//10 stay exact rationals through GIAC, and to_julia gives them back as 1//10.

Multiprecision reals (REAL) are read from their decimal, which carries all their digits; float keeps the BigFloat precision the decimal implies.

Fractions (FRAC) read as Rational{Int64}, or Rational{BigInt} when a part does not fit a machine integer. GIAC stores a complex number with a rational part as a fraction whose numerator is a Gaussian integer, so such a number reads as a Complex of Rationals:

to_julia(giac_eval("(3+2*i)/4"))       # 3//4 + 1//2*im
to_julia(giac_eval("[1/2, 1/3+i/4]"))  # Complex{Rational{Int64}}[1//2 + 0//1*im, 1//3 + 1//4*im]
Complex(giac_eval("(3+2*i)/4"))        # 3//4 + 1//2*im
Rational(giac_eval("(3+2*i)/4"))       # InexactError, as for Rational(3//4 + 1//2*im)

Before, these raised ArgumentError (the Gaussian numerator could not be parsed as an integer), and Complex(g) of any fraction raised MethodError.

GIAC's epsilon is left as it was. GIAC's evalf of a rootof to n digits sets epsilon, the tolerance of its numeric algorithms, to 10⁻ⁿ for the rest of the session; numeric integrals then return two estimates instead of a value. Giac.Commands.evalf(x, n) and invoke_cmd(:evalf, x, n) put epsilon back afterwards, and so does to_julia, which reduces a constant with evalf(x, 18). Assigning epsilon yourself (giac_eval("epsilon:=1e-8")) is unaffected.
